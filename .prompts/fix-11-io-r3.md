## 跨模块约定（模块间不能 import，靠约定对齐）
- **多段特征**（GenBank `join(...)` / SnapGene 多 Segment）：
  - `SequenceFeature.notes.segments = ["s-e", "s-e", ...]`，每段为 0-based 左闭右开的文档坐标字符串（如 `"10-200"`），按生物学顺序排列；负链特征按 5'→3' 顺序。
  - 该特征的 `start`/`end` 为第一段起点到最后一段终点的整体覆盖区间（环状跨零点同样适用）。
  - 没有 `segments` 的特征视为单段。
- **蛋白文档**（schema 中没有，由各模块用相同结构各自声明，不得 import 彼此）：
```ts
export interface ProteinFeature { id: string; name: string; type: string; start: number; end: number; color: string; notes?: Record<string, string[]> } // 氨基酸坐标，0-based 左闭右开
export interface ProteinDocument { id: string; name: string; sequence: string; description?: string; features: ProteinFeature[]; createdAt: string; updatedAt: string }
```
- **FASTQ / 测序读长**：
```ts
export interface SequencingRead { id: string; name: string; sequence: string; qualities: number[] } // Phred
```

## 任务：NCBI 导入、多段特征、蛋白文件、FASTQ、更多格式

### 1. NCBI 按登录号导入
```ts
export async function fetchFromNCBI(accession: string, opts?: { db?: 'nuccore' | 'protein'; fetchImpl?: typeof fetch; apiKey?: string }): Promise<PlasmidDocument | ProteinDocument>
export function normalizeAccession(input: string): { accession: string; db: 'nuccore' | 'protein' } | null
```
- 使用 NCBI E-utilities 的 efetch：`https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=nuccore&id=...&rettype=gbwithparts&retmode=text`。该接口支持 CORS。
- 接受的输入：带版本号的登录号如 `L09137.2`、不带版本号如 `NM_000546`、NCBI 网页 URL。
- 识别蛋白登录号（如 `NP_`、`XP_`、`WP_`、`YP_`、3 字母 + 5 数字的形式）后改用 protein 库，用 rettype=gp。
- 失败时抛出带原因的 Error：网络错误、登录号不存在、序列超过 5 Mb。
- 解析时复用本模块现有的 GenBank 解析。
- 测试注入 `fetchImpl` mock，读取本地 `src/app/samples/pUC19.gb` 作为响应，不得访问真实网络。

### 2. 多段特征
- GenBank 中的 `join(...)`、`order(...)`、`complement(join(...))` 解析为单个特征，带 `notes.segments`（格式见约定）。
- SnapGene `.dna` 中的多 Segment 特征同样处理。
- 导出时反向生成：GenBank 写 join；`.dna` 写多个 Segment。
- 测试：构造含 join 的 GenBank，往返后结果一致。

### 3. 蛋白文件
```ts
export async function parseProteinFile(fileName: string, data: string | ArrayBuffer): Promise<ProteinDocument[]>
export function exportProteinToFasta(p: ProteinDocument): string
export function exportProteinToGenPept(p: ProteinDocument): string
export function isProteinFile(fileName: string, data: string | ArrayBuffer): boolean
```
- 支持的格式：
  - SnapGene `.prot`：TLV 格式，cookie 中的 seqType 为蛋白，蛋白序列段与特征 XML。按公开格式描述实现。
  - GenPept：`.gp` 文件或 LOCUS 行含 aa 的 GenBank 文本。
  - 蛋白 FASTA：字母组成判断为蛋白时。
- `isProteinFile` 供集成层分流用：扩展名或内容判断为蛋白时返回 true。
- 现有的 `parseBioFile` 行为不变。

### 4. FASTQ 与读长
```ts
export function parseFastq(text: string): SequencingRead[]
```
- 支持多条记录、Phred+33。
- 遇到非法格式时抛出错误。
- 支持 `.fastq` / `.fq`；`.gz` 不处理，给出错误提示即可。

### 5. 更多导入格式
确保 `parseBioFile` 至少支持以下格式。teselagen bio-parsers 已支持的直接复用，不支持的自行实现：
- ApE `.ape`（GenBank 变体）
- Vector NTI 导出的 GenBank
- DNASTAR `.seq`（纯文本，可能带头部）
- Serial Cloner `.xdna`（二进制，按公开描述）
- Clone Manager `.cm5`：能解析则支持，不能则给出清晰的错误
- Benchling / Geneious 导出的 GenBank 变体
- SBOL XML：若库支持
- 纯文本序列
每种格式都要有测试；在测试内构造最小样例即可。
